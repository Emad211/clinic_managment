# واژگانِ مشترک (Ubiquitous Language)

زبانِ مشترکِ تیم، مالک و پزشک. هر اصطلاح یک معنای دقیق دارد و در کد/سند/گفتگو یکسان به‌کار می‌رود.

| فارسی | English | تعریفِ دقیق در این پروژه |
|---|---|---|
| بیمار | Patient | شخص؛ هویتِ یکتا با **کدِملی (`national_id`)**. مالکِ هویت = حسابداری. |
| کدملی | national_id | **کلیدِ مرزیِ بینِ دو اپ.** تنها شناسه‌ای که هر دو Context می‌شناسند. |
| پروندهٔ پیوند | patient_link | آینهٔ محلیِ بیمار در اپِ تخصصی (`patient_links`)؛ `pid` = `patient_links.id`. |
| پذیرش | Reception | نقطهٔ تماسِ مالیِ بیمار (در `webapp`)؛ فاکتور را باز/می‌بندد. |
| فاکتور | Invoice | واحدِ مالی در حسابداری؛ وضعیتِ `open`→`closed`. |
| بازکردنِ فاکتور | Invoice opened | پذیرش فاکتورِ ویزیت را می‌سازد → بیمار واردِ صفِ پزشک می‌شود. |
| بستنِ فاکتور | Invoice closed | همهٔ آیتم‌ها پرداخت شد → رویدادِ `invoice.closed` (تریگرِ تشکر/دعوت). |
| ویزیت | Encounter / Visit | ملاقاتِ بالینی؛ در حسابداری آیتمِ فاکتور، در تخصصی پروندهٔ بالینی. |
| پروسیجر | Procedure | خدمتِ عملی (شستشوی گوش/پانسمان/بخیه/…)؛ `procedures.procedure_type` (متنِ آزاد). |
| صفِ پزشک | Doctor queue | فهرستِ زندهٔ بیمارانِ دارای فاکتورِ ویزیتِ **باز** امروز (در نوبت/انجام‌شده). خواندنِ زنده، نه رویداد. |
| پیگیری | Follow-up Task | کارِ ورک‌لیست (`followup_tasks`): تماس/اقدامِ بعدی؛ `remote` یا `in_person`. |
| پروتکلِ مراقبت | Care Protocol | تمپلیتِ داده‌محورِ «چه چیزی، هر چند وقت» (`care_protocols` + `clinical_rules`). |
| ثبت‌نام (در پروتکل) | Enrollment | بیمار تحتِ یک پروتکل؛ تسکِ سررسیده از آن **materialize** می‌شود. |
| رویدادِ تعامل | Engagement Event | پیکربندیِ «رویداد→کانال» (`engagement_events`): چه چیزی به sms/worklist برود. |
| صفِ تأییدِ پیام | Approval Queue | هر پیامکِ خودکار پیش از ارسال منتظرِ **تأییدِ پزشک** (`engagement_approvals`). |
| موتورِ پیگیری | Follow-up engine | قلبِ سیستم: پروتکل→ثبت‌نام→تسک→ارسالِ زمانی/واکنشی. |
| پیشنهاد، تأیید با پزشک | Suggestion-only | اصلِ ایمنی: سیستم پیشنهاد می‌دهد، **پزشک تصمیم می‌گیرد**؛ هیچ اقدامِ بالینیِ خودکار. |
| پلِ حسابداری | Accounting bridge / ACL | اتصالِ **فقط‌خواندنیِ** تخصصی به `clinic_new.db` (`mode=ro`). |
| درز / Outbox | Integration seam | جدولِ رویدادِ افزایشی در حسابداری که تخصصی مصرف می‌کند (ADR-0003). |
| رویداد | Domain Event | واقعیتی که رخ داده (مثلِ `invoice.closed`)؛ قراردادِ پایدارِ بینِ Contextها. |
| مصرف‌کنندهٔ idempotent | Idempotent consumer | پردازشِ رویداد که اجرای دوباره‌اش اثرِ اضافه ندارد (لجرِ UNIQUE). |
| Bounded Context | Bounded Context | مرزِ مدلِ دامنه: حسابداری / بالینی-تعامل / پلِ نسخه‌نویسی. |
| ACL | Anti-Corruption Layer | لایه‌ای که Contextِ پایین‌دست را از مدلِ بالادست محافظت می‌کند. |
| مستأجر | Tenant | یک درمانگاه در مدلِ آیندهٔ چندمستأجره (Postgres+RLS). |
| نسخهٔ آزاد | Free prescription | نسخهٔ چاپیِ غیربیمه‌ایِ ساختِ اپ (`prescriptions.mode='free'`). |
| اعتبار (نه تخفیف) | Wallet credit | قابِ قانونیِ پروموشن (`wallet_*`)؛ «اعتبار»، نه «تخفیف/رایگان». |
