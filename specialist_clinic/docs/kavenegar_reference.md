# مرجع API کاوه‌نگار (Kavenegar) — پنل پیامک فعالِ کلینیک

> این سند، داده‌های فنیِ گردآوری‌شده از مستندات رسمی کاوه‌نگار (`kavenegar.com/rest.html`) و SDK رسمی پایتون است،
> به‌علاوهٔ نکاتِ پیاده‌سازی در همین اپ. **پنلِ پیامکِ فعالِ پروژه از این پس کاوه‌نگار است** (مدیانا به‌عنوان گزینهٔ جایگزین در کد باقی می‌ماند).
>
> هر زمان تعریفِ ارسال/خطا در کاوه‌نگار تغییر کرد، این فایل + `src/services/sms/kavenegar_provider.py` را هم‌زمان به‌روز کنید.

---

## ۱) نگاه کلی

- **شرکت:** کاوه‌نگار — سرویس‌دهندهٔ پیامک و تماس صوتی ایرانی.
- **پروتکل:** REST روی HTTPS، خروجی `JSON` یا `XML`.
- **تفاوتِ کلیدی با مدیانا:** کلیدِ API بخشی از **مسیرِ URL** است، نه هدرِ `X-API-KEY`.
- **واحدِ اعتبار:** ریال (در `account/info` فیلد `remaincredit`).
- **طولِ پیام:** هر بخشِ پیامکِ فارسی **۷۰ کاراکتر** (یونی‌کد)، لاتین ۱۶۰ کاراکتر؛ پیامِ چندبخشی تا حداکثر **۹۰۰ کاراکتر**.

---

## ۲) Base URL و احراز هویت

```
https://api.kavenegar.com/v1/{API-KEY}/{scope}/{method}.{json|xml}
```

- `{API-KEY}` در **مسیر** قرار می‌گیرد (نه در هدر و نه در body). نمونه از کلیدِ این پروژه: یک رشتهٔ هگزِ بلند که در جدولِ `settings` ذخیره می‌شود (هرگز در گیت/کد).
- متدها معمولاً هم `GET` و هم `POST` را می‌پذیرند؛ برای پیامِ فارسیِ طولانی **POST با `application/x-www-form-urlencoded`** امن‌تر است.
- در `GET`، پارامترها باید **URL-encode** شوند.

---

## ۳) قالبِ پاسخ (Envelope)

همهٔ پاسخ‌ها دو بخش دارند: `return` (وضعیتِ کلیِ درخواست) و `entries` (دادهٔ نتیجه).

**نمونهٔ پاسخِ `sms/send`** (`entries` یک **آرایه** از پیام‌هاست):

```json
{
  "return": { "status": 200, "message": "تایید شد" },
  "entries": [
    {
      "messageid": 8792343,
      "message": "متن پیامک",
      "status": 1,
      "statustext": "در صف ارسال",
      "sender": "10004346",
      "receptor": "09123456789",
      "date": 1356619709,
      "cost": 120
    }
  ]
}
```

**نمونهٔ پاسخِ `account/info`** (`entries` یک **شیء** است، نه آرایه):

```json
{
  "return": { "status": 200, "message": "تایید شد" },
  "entries": { "remaincredit": 1000000, "expiredate": 1357771261, "type": "postpaid" }
}
```

> قاعدهٔ تشخیصِ موفقیت در کد: **`return.status == 200`**. مقدار `entries[i].status` وضعیتِ *تحویلِ پیام* است (نه موفقیتِ درخواست) و در لحظهٔ ارسال معمولاً `1` (در صفِ ارسال) است.

## ۴) متدها

### ۴.۱ ارسالِ ساده — `sms/send` (پُرکاربردترین)
`POST|GET  /v1/{KEY}/sms/send.json`

| پارامتر | اجباری | نوع | توضیح |
|---|---|---|---|
| `receptor` | بله | String | شمارهٔ گیرنده؛ چند شماره با کاما (حداکثر ۲۰۰ در هر فراخوان) |
| `message` | بله | String | متنِ پیام (در GET باید URL-encode شود) |
| `sender` | خیر | String | خطِ ارسال؛ خالی = خطِ پیش‌فرضِ حساب |
| `date` | خیر | UnixTime | زمان‌بندیِ ارسال؛ خالی = آنی |
| `type` | خیر | int | نوعِ نمایش (۰ فلش … رجوع به §۷) |
| `localid` | خیر | Long | شناسهٔ محلی برای **جلوگیری از ارسالِ تکراری** (idempotency) |
| `hide` | خیر | byte | `1` = مخفی‌کردنِ شمارهٔ گیرنده در گزارش‌ها |
| `tag` | خیر | String | برچسب (حداکثر ۲۰۰ کاراکتر) |

### ۴.۲ ارسالِ گروهی نظیربه‌نظیر — `sms/sendarray`
`POST  /v1/{KEY}/sms/sendarray.json` — `receptor`/`sender`/`message` هرکدام **آرایهٔ JSON هم‌طول**اند (هر گیرنده پیام/خطِ خودش). برای کمپین‌های بزرگ کارآمدتر از تکرارِ `send` است.

### ۴.۳ کدِ تأیید/الگو (OTP) — `verify/lookup`
`POST|GET  /v1/{KEY}/verify/lookup.json`

| پارامتر | اجباری | توضیح |
|---|---|---|
| `receptor` | بله | یک شماره |
| `token` | بله | مقدارِ متغیر (بدونِ فاصله، حداکثر ۱۰۰ کاراکتر) |
| `token2`,`token3` | خیر | متغیرهای بعدیِ الگو |
| `token10` | خیر | توکنِ با حداکثر ۵ فاصله |
| `token20` | خیر | توکنِ با حداکثر ۸ فاصله |
| `template` | بله | نامِ **الگوی تأییدشده** در پنل |
| `type` | خیر | `sms` (پیش‌فرض) یا `call` (اعلامِ صوتی) |

> مزیتِ `verify/lookup`: از خطِ خدماتیِ مشترک ارسال می‌شود، **محدودیتِ ساعتِ شب ندارد** و برای پیام‌های تراکنشی/یادآوریِ کوتاه ایده‌آل است — اما متن باید در قالبِ از پیش‌تأییدشده باشد.

### ۴.۴ وضعیتِ تحویل
- `sms/status` — `POST|GET` — `messageid` (چندتایی با کاما، حداکثر ۵۰۰)؛ فقط **۴۸ ساعتِ اخیر**.
- `sms/statuslocalmessageid` — بر اساسِ `localid`؛ فقط **۱۲ ساعتِ اخیر**.
- `sms/statusbyreceptor` — `receptor` + `startdate` (+`enddate`)؛ بازهٔ حداکثر ۱ روز.

### ۴.۵ صندوقِ خروجی / دریافتی
- `sms/select` — جزئیاتِ پیام بر اساس `messageid` (نیازمندِ IP whitelist).
- `sms/selectoutbox` — `startdate`(+`enddate`,`sender`)؛ بازهٔ ۱روزه، حداکثر ۵۰۰ رکورد (IP whitelist).
- `sms/latestoutbox` — `pagesize`(+`sender`)؛ آخرین ارسال‌ها.
- `sms/countoutbox` — شمارشِ ارسال‌ها در بازه (+`status`).
- `sms/cancel` — لغوِ پیامِ **زمان‌بندی‌شده** (هزینه برمی‌گردد).
- `sms/receive` — `linenumber`+`isread`؛ دریافتیِ خط (حلقه تا رسیدنِ count<100).
- `sms/countinbox` — شمارشِ دریافتی‌ها (بازهٔ حداکثر ۶۰ روز).

### ۴.۶ مدیریتِ خط و لیستِ سیاه
- `line/blocked/list` | `line/blocked/add` (POST) | `line/blocked/exists` | `line/blocked/remove` (DELETE) — مدیریتِ شماره‌های بلاک‌شدهٔ هر خط.

### ۴.۷ تماسِ صوتی — `call/maketts`
`POST|GET  /v1/{KEY}/call/maketts.json` — `receptor`+`message` (متنِ تبدیل‌به‌گفتار)، `date`,`localid`,`repeat`,`tag`.

### ۴.۸ حساب
- **`account/info`** — `GET`، **بدونِ پارامتر** → `remaincredit` (ریال)، `expiredate` (UnixTime)، `type`. *(ارسال نمی‌کند و هزینه ندارد؛ بهترین راهِ تستِ صحتِ کلید.)*
- `account/config` — تنظیماتِ حساب: `apilogs` (`justfaults|enabled|disabled`)، `debugmode`، `defaultsender`، `mincreditalarm` (ریال)، `resendfailed`.

## ۵) کدهای وضعیتِ عمومی (`return.status`)

| کد | معنی |
|---|---|
| **200** | درخواست تأیید شد |
| 400 | پارامترها ناقص است |
| 401 | حساب کاربری غیرفعال است |
| 402 | عملیات ناموفق بود |
| **403** | کدِ شناسایی (API-Key) نامعتبر است |
| 404 | متد نامشخص است |
| 405 | متدِ Get/Post اشتباه است |
| 406 | پارامترهای اجباری خالی ارسال شده‌اند |
| 407 | دسترسی امکان‌پذیر نیست (نیازمندِ IP مجاز) |
| 409 | سرور پاسخ‌گو نیست؛ بعداً تلاش کنید |
| **411** | دریافت‌کننده نامعتبر است |
| **412** | ارسال‌کننده نامعتبر است |
| **413** | پیام خالی است یا طولِ پیام بیش از حد است |
| 414 | حجمِ درخواست بیش از حد (۲۰۰ گیرنده در هر ارسال، ۵۰۰ در استعلام) |
| 415 | اندیسِ شروع بزرگ‌تر از تعدادِ کل است |
| 416 | IP سرویس‌دهنده با IP ثبت‌شده مطابقت ندارد |
| 417 | تاریخِ ارسال اشتباه است (گذشته/فرمتِ نادرست) |
| **418** | اعتبارِ حساب کافی نیست |
| 422 | کاراکترِ نامناسب در داده‌ها |
| **424** | الگو یافت نشد یا تأیید نشده است |
| 426 | این متد نیازمندِ سرویسِ پیشرفته است |
| 428 | کدِ تماسِ صوتی باید عددی باشد |
| **430** | حساب کاربری **احراز هویت نشده** است (باید در پنل کاوه‌نگار احراز هویت/KYC کامل شود) |
| 431 | ساختارِ کد صحیح نیست |
| 432 | پارامترِ کد در متنِ پیام یافت نشد |

*(کدهای پررنگ در ادپترِ `kavenegar_provider.py` به پیامِ فارسی نگاشت شده‌اند.)*

## ۸) محدودیت‌ها و قواعد

- **طولِ بخش:** ۷۰ کاراکترِ فارسی / ۱۶۰ لاتین در هر بخش؛ تا ۹۰۰ کاراکتر چندبخشی. هزینه به ازای هر بخش حساب می‌شود.
- **تعدادِ گیرنده:** حداکثر ۲۰۰ در هر `send`؛ استعلامِ وضعیت حداکثر ۵۰۰ شناسه.
- **فرمتِ شماره:** `09123456789` (و نیز `+98…`/`0098…`/`9123456789`).
- **تاریخ:** همهٔ فیلدهای زمانی **UnixTime** هستند.
- **IP whitelist:** متدهای `select`/`selectoutbox` و برخی گزارش‌ها نیازمندِ ثبتِ IP در پنل‌اند.

### نکاتِ عملیاتی/قانونی (نه فیلدِ API)
- **خط‌ها:** خطوطِ `1000…`/`2000…`/`3000…` معمولاً اشتراکی/تبلیغاتی‌اند؛ خطِ اختصاصی و خطوطِ **خدماتیِ ۹۸۰۰۰…** برای پیام‌های تراکنشی/یادآوری.
- **خدماتی در برابر تبلیغاتی:** پیامِ خدماتی (یادآوری نوبت، اطلاع‌رسانیِ درمانی) از خطِ خدماتی **بدونِ محدودیتِ ساعتِ شب** ارسال می‌شود؛ پیامِ **تبلیغاتی** مشمولِ محدودیتِ ارسالِ شبانه (تقریباً ۸ صبح تا ۲۳) و قابلِ لغو با کدِ مخالفت است.
- در همین اپ، گاردریلِ **ساعتِ آرام (۸–۲۱)** و **opt-out** در موتورِ تعامل از قبل این قواعد را رعایت می‌کند؛ بنابراین یادآوری‌ها بهتر است از خطِ خدماتی/`verify/lookup` بروند.

## ۹) پیاده‌سازی در این اپ

- **ادپتر:** [`src/services/sms/kavenegar_provider.py`](../src/services/sms/kavenegar_provider.py) — کلاسِ `KavenegarProvider(SmsProvider)` با `send()` و `get_balance()` فقط با stdlib (`urllib`).
  - موفقیت = `return.status == 200`؛ `provider_msgid = entries[0].messageid`.
  - خطای **timeout** → `SendResult(pending=True)` («در انتظار تأیید») و **بدونِ retry** (دقیقاً مثل رفعِ باگِ مدیانا — تا ارسالِ دوباره رخ ندهد).
  - شکستِ واقعیِ اتصال (refused/DNS) → `failed`.
- **انتخابِ پنل:** `get_provider()` در [`provider.py`](../src/services/sms/provider.py) بر اساسِ تنظیمِ `sms_provider` (`kavenegar`|`mediana`) پنلِ فعال را برمی‌گرداند؛ اگر کلیدِ پنلِ منتخب نبود به پنلِ دارای کلید، و در نهایت به `NullProvider` (شبیه‌سازی) برمی‌گردد.
- **کلیدهای `settings`** (جدولِ key/value، در `specialist.db` — خارج از گیت):
  - `sms_provider` = `kavenegar`
  - `kavenegar_api_key` = «کلیدِ پنل»
  - `kavenegar_sender` = «خطِ ارسال» (اختیاری)
  - `kavenegar_timeout` = ثانیهٔ مهلتِ انتظار (پیش‌فرض ۴۵)
- **شمارشِ بخش‌ها:** UI از ۷۰ کاراکتر برای هر بخشِ فارسی استفاده می‌کند (`sms.py`، `_hub`/composer).

### پیشنهادِ آینده (نه‌ضروریِ امروز)
- استفاده از `localid` (همان `sms_messages.id`) برای idempotencyِ سمتِ کاوه‌نگار.
- صفِ استعلامِ `sms/status` برای به‌روزرسانیِ وضعیتِ «تحویل‌شده» (کد ۱۰) در `sms_messages`.
- مهاجرتِ یادآوری‌ها به `verify/lookup` با الگوهای تأییدشده تا از محدودیتِ ساعتِ شب رها شوند.

## ۱۰) منابع

- مستندِ رسمیِ REST کاوه‌نگار: `https://kavenegar.com/rest.html`
- SDK رسمیِ پایتون: `https://github.com/kavenegar/kavenegar-python`
  - راه‌اندازی: `KavenegarAPI('APIKey', timeout=20)` (پیش‌فرض ۱۰ ثانیه)
  - `api.sms_send({'sender','receptor','message'})` · `api.verify_lookup({'receptor','template','token','type'})`
  - استثناها: `APIException`, `HTTPException`
