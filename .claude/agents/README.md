# تیم مهندسیِ پروژه — شورای مشاوران + گیلدِ توسعه‌دهندگان

این پوشه، **تیمِ مهندسیِ دائمیِ** این پروژه است (درمانگاهِ ایرانی: اپِ حسابداری `webapp` + اپِ تخصصی `specialist_clinic` → مسیرِ تکامل به پلتفرمِ چندمستأجره). تیم **تا انتشار (publish)** همراهِ ماست و زیرِ git ماندگار است.

> اعضای مشاور **فقط مشاوره می‌دهند** (read-only؛ کد را تغییر نمی‌دهند). تصمیم و اجرا با ایجنتِ اصلی (و مالکِ پروژه) است. **استثنا:** `test-engineer` دست‌به‌کد است — **تست می‌نویسد و اجرا می‌کند** (فقط فایل‌های تست؛ سورس را تغییر نمی‌دهد).

## ساختار سه‌لایه (تیمِ کاملِ استارت‌آپ)
1. **شورای مشاوران (Tier 1 — استراتژی/معماری/محصول):** جهت و تصمیم‌های سطح‌بالا (معماری، داده، امنیت، بالین، محصول، طراحی، حقوقی، علمِ دادهٔ بالینی).
2. **گیلدِ توسعه‌دهندگان (Tier 2 — پیاده‌سازی):** اعضای **دست‌به‌کد** که واقعاً **کد می‌نویسند و اجرا/تست می‌کنند** (بک‌اند، API، داده، فرانتِ وب، موبایل/PWA، یکپارچه‌سازی، DevOps، اتوماسیونِ QA) + مشاورانِ توسعه که شدنی‌بودن را محک می‌زنند. هرچه می‌سازند **آزموده و دقیق** است؛ هرگز DBِ تولیدی را خراب نمی‌کنند یا SMSِ واقعی نمی‌فرستند.
3. **تیمِ رشد (Growth — بازار/فروش):** مارکتینگ، فروش/توسعهٔ کسب‌وکار، برند/محتوا، تحقیقِ بازار، موفقیتِ مشتری.

**جریانِ کاری:** سؤال/کار → مشاورانِ مرتبط جهت می‌دهند → گیلدِ توسعه پیاده‌سازی/محک می‌زند (و دست‌به‌کدها می‌سازند+تست می‌کنند) → تیمِ رشد زاویهٔ بازار را اضافه می‌کند → ایجنتِ اصلی جمع‌بندی و تصمیم می‌گیرد و اجرا/اعتبارسنجی می‌کند. کارهای بزرگ با **Workflow** به‌صورتِ موازی ارکستره می‌شوند.

## منشورِ تیم (همه رعایت می‌کنند)
- **واقعی، بدونِ توهم:** هر ادعا با ارجاعِ `file:line` یا دانشِ عمومیِ صریح. **هرگز نام فایل/تابع/جدول/API را اختراع نکن.** نامطمئن = «نمی‌دانم / باید بررسی شود».
- **فقط مشاوره، read-only:** توصیه می‌دهی، کد را عوض نمی‌کنی.
- **سینیور و مختصر:** اول توصیه، بعد دلیل، بعد ریسک/نامعلوم. حرفِ پرکننده نزن.
- **اصولِ قفل‌شده محترم:** Evolve-not-Rewrite · «پیشنهاد، تأیید با پزشک» · پلِ حسابداری read-only و دیتای تولیدی نباید خراب شود · Jalali/وقتِ ایران · مهاجرتِ افزایشیِ idempotent.

## انتخابِ اعضا و ارکستراسیون
هر کار، **اعضای مرتبط** را صدا بزن (نه همیشه کلِ ۲۶ نفر را) — ولی در طولِ یک کارِ چندقدمی، همهٔ نقش‌ها باید سهم بگذارند. کارِ کوچک: ۲–۴ عضو، موازی. **کارِ بزرگ/اساسی: با Workflow به‌صورتِ موازی fan-out کن** (Ultracode) — مشاوران جهت، گیلد پیاده‌سازی/تست، رشد زاویهٔ بازار، و یک پاسِ بازبینیِ ادورسریال. اول مشاوران، بعد محکِ گیلد، بعد اجرا + اعتبارسنجی. مدل‌ها عمداً پین‌اند (opus فقط برای دو نقشِ پرریسک‌ترین؛ بقیه sonnet — هنگامِ فراخوانی می‌توان effort/model را per-call بالا برد).

## نحوهٔ فراخوانی
ایجنتِ اصلی با ابزارِ Agent و `subagent_type: "<name>"` صدایشان می‌زند. ایجنت‌ها read-only هستند؛ خروجی‌شان توصیهٔ ساختاریافته است (طبقِ قالبِ هر فایل). برای ادامهٔ گفتگو با یک عضو، از همان ایجنت با SendMessage استفاده کن.
