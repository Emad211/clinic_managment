# نقشهٔ راهِ حقوقی — «حلقه» (خوشهٔ R نقشهٔ MVP)

> **وضعیت:** پیش‌نویسِ نقشهٔ راه — منتظرِ تأییدِ مالک برای ورود به قدمِ L1.
> **پایلوتِ اول: کلینیکِ سیب، گرگان** (مشتریِ فعلیِ اپِ حسابداریِ لوکال — رابطهٔ تجاریِ موجود).
> **دیسکلیمرِ دائمی:** تیمِ حقوقیِ ایجنتی جایگزینِ وکیلِ دارای‌پروانه **نیست**. خروجیِ این نقشه،
> «بستهٔ آمادهٔ بررسیِ وکیل» است؛ **امضا و نهایی‌سازی فقط با وکیلِ رسمی** (گِیتِ R4).

## جایگاه در نقشهٔ MVP

- **R3 (قدم ۷۱):** انتخابِ پایلوت ✅ (سیب/گرگان — اعلامِ مالک 2026-07-04) + ورودی‌های تجاری + **LOI** → خروجیِ قدمِ L4.
- **R4 (قدم ۷۲):** بستهٔ حقوقیِ کامل + قراردادِ امضاشده — **گِیتِ سختِ پیش از هر PHIِ واقعی** → خروجیِ قدمِ L5.
- خوشه‌های V/W/X (ورودِ بیمارِ واقعی، go-live) همه پشتِ R4 می‌مانند.

## تیم

| نقش | ایجنت | مدل |
|---|---|---|
| وکیلِ ارشدِ حقوقِ سلامت — سرپرست | `health-law-counsel` | opus |
| وکیلِ حفاظت از داده | `data-protection-counsel` | opus |
| وکیلِ قراردادها (دست‌به‌قلم، فقط این پوشه) | `contracts-counsel` | sonnet |
| محققِ متنِ قانون (منابعِ رسمی) | `legal-research-analyst` | sonnet |
| محققِ رگولاتوری/رویهٔ بازار | `regulatory-intel-researcher` | sonnet |
| پشتیبان‌های موجود | `legal-compliance-advisor` · `security-privacy-advisor` · `sales-bizdev-advisor` | sonnet |

**الگوی هر قدم (گردهمایی):** ① سؤال‌های تحقیقِ دقیق (سرپرست) → ② **تحقیقِ اینترنتیِ چندمرحله‌ایِ موازی** (دو محقق: سیاهه → عمق‌خوانی → ممیزیِ استناد) → ③ سنتزِ مواضع (دو وکیلِ ارشد، اختلاف‌نظر صریح ثبت) → ④ پیش‌نویس (`contracts-counsel`، فقط زیرِ `halqe/docs/legal/`) → ⑤ بازبینیِ مستقلِ ارکستریتور + کامیت → ⑥ **گِیتِ مالک** (و برای متنِ نهایی: وکیلِ رسمی).

**قاعدهٔ آهنینِ ضدتوهم:** هیچ شمارهٔ ماده/قانون/مصوبه بدونِ رؤیتِ منبعِ رسمی؛ هر ادعا = منبع + لینک + تاریخِ رؤیت + سطحِ قطعیت (`✅ رسمی` / `⚠️ ثانویه` / `❓ یافت‌نشد`). «یافت نشد» خروجیِ معتبر است.

## قدم‌ها

### ✅ L1 — نقشهٔ حقوقیِ پایه (regulatory landscape) — **کامل شد (2026-07-04)**
**خروجی:** [`L1_legal_landscape.md`](L1_legal_landscape.md) (موضع + رتبهٔ ۱۲ ریسک R-1..R-12 + ۱۴ نامعلومِ وکیل‌خواه + ۷ تصمیمِ قفل‌شده) + ۴ فایلِ خامِ [`research/L1a..L1d`](research/).
**یافتهٔ محوری:** امروز رژیمِ الزام‌آور = **ق.تجارتِ الکترونیکی ۵۸/۵۹/۷۱ + رازداریِ ۶۴۸ + جرائمِ رایانه‌ای ۷۴۵/۷۳۹** (همه کیفری)؛ قانونِ جامعِ دادهٔ شخصی/سلامت **هنوز لازم‌الاجرا نیست**؛ بومی‌سازیِ اجباری بر بخشِ خصوصی الزامِ صریح ندارد (آروان = کاهشِ ریسک، نه رفعِ تکلیف)؛ افقِ نزدیک = **نقشه‌راه سلامتِ الکترونیک مهر ۱۴۰۴ + مجوزِ «اپراتورِ مجازِ سلامت»** (تا شهریور ۱۴۰۵). ریسکِ زندهٔ eNamad/دارورسانی را مدلِ B2B/read-only دور می‌زند.
**اقدام‌های مالک (§۷ سند):** استعلامِ دستیِ سامانهٔ مجلس · ۳ سؤال از سیب · درخواستِ کتبیِ افتا/دیتاسنتر از آروان · تأییدِ ۷ تصمیمِ معماری.

<details><summary>شرحِ اولیهٔ L1 (بایگانی)</summary>

**هدف:** فهرستِ مستندِ «چه قوانینی بر ما حاکم‌اند» در ۴ ترکِ تحقیقِ **موازی**:
- **L1a — دادهٔ سلامت و پروندهٔ پزشکی:** محرمانگی/رازداری، مالکیت و نگه‌داریِ پرونده، افشای مجاز، تکالیفِ کلینیک و پزشک.
- **L1b — حفاظت از دادهٔ شخصی و فضای مجازی:** موادِ دادهٔ قوانینِ موجود (تجارتِ الکترونیکی، جرایمِ رایانه‌ای و…)، مصوباتِ شورای عالی فضای مجازی، **وضعِ روزِ لایحه/طرحِ حفاظت از داده‌های شخصی**، الزاماتِ میزبانیِ داخلی/افتا.
- **L1c — سلامتِ دیجیتال:** تله‌مدیسین/ویزیتِ از‌راه‌دور، جایگاهِ حقوقیِ CDS (موتورِ suggestion-only)، نسخهٔ الکترونیک، مجوز/گواهیِ سکوهای سلامت + **رویهٔ سکوهای مشابه** (پذیرش۲۴/دکترتو/…).
- **L1d — پیامک و ارتباطات:** پیامکِ درمانی/یادآور در برابرِ تبلیغاتی، خطوطِ خدماتی، سامانهٔ ۱۹۵/opt-out، KYC.

هر ترک ۳ مرحله: سیاهه → عمق‌خوانی → ممیزیِ استناد. سپس سنتزِ دو وکیل.
**خروجی:** `L1_legal_landscape.md` — جدولِ قانون→تکلیف→اثر بر حلقه→قطعیت + فهرستِ «نامعلوم‌های وکیل‌خواه».
**گِیت:** تأییدِ مالک بر تصویرِ کلی و اولویت‌ها.
</details>

### ✅ L2 — میزبانیِ PHI روی آروان + الزاماتِ DPA — **کامل شد (2026-07-04)**
**خروجی:** [`L2_phi_hosting_arvan.md`](L2_phi_hosting_arvan.md) (تعهداتِ آروان + تحلیلِ شکاف + حملهٔ ۱۳۹۹ + یافتهٔ OFAC) + [`drafts/dpa_arvan_checklist.md`](drafts/dpa_arvan_checklist.md) (۱۰ موردِ مطالبهٔ کتبی).
**یافته‌ها:** آروان نقشِ controller/processor را پذیرفته + گواهیِ افتا + دیتاسنترِ داخلیِ قابلِ‌انتخاب + گزارشِ شفافیت (همه کاهندهٔ ریسک) — **ولی تعهداتِ کلیدیِ DPAِ سلامت (محرمانگیِ صریح، عدمِ انتقال، اطلاع‌رسانیِ نشتِ زمان‌دار، حذفِ پایانِ قرارداد، سقفِ مسئولیت) عمومیِ کتبی تأیید نشد** (متنِ کاملِ اسناد پشتِ JS بود). ⚠️ **آروان از خرداد ۱۴۰۲ در تحریمِ OFAC** (اثر بر اعتماد + وابستگیِ بین‌المللیِ آینده). درسِ حملهٔ ۱۳۹۹: بک‌آپِ رمزنگاری‌شدهٔ خارج از AZ + رمزنگاریِ سطحِ اپ + چند-AZ الزامی.
**اقدامِ مالک:** ۱۰ موردِ چک‌لیست را کتباً از آروان بخواه + متنِ کاملِ ToS/SLA/Privacy را بگیر.

### ✅ L3 — چارچوبِ رضایتِ بیمار (consent) — **کامل شد (2026-07-04)**
**خروجی:** [`L3_consent_framework.md`](L3_consent_framework.md) (چک‌لیستِ ۱۴-عنصری + ساختارِ ۵-بخشی) + [`drafts/consent_patient_fa.md`](drafts/consent_patient_fa.md) (فرمِ رضایتِ بیمارِ آمادهٔ بازبینیِ وکیل، با واترمارک).
**یافته‌ها:** چک‌لیستِ رضایتِ معتبر از مواد ۵۸/۵۹ ق.ت.ا استخراج شد؛ ۶ نمونهٔ واقعیِ متن‌خوانده (فرمِ پذیرشِ heyva، پذیرش۲۴، دکترتو، آیین‌نامهٔ اخلاق، healthlaw، نظام‌پزشکی). **یافتهٔ طلایی:** رویهٔ ایران «اجازه‌نامهٔ استفاده از اطلاعاتِ پروندهٔ بیمار» را رضایتِ مستقلِ پذیرش می‌داند؛ دکترتو الگوی دو-نقطه‌ای opt-in پیامک + استنادِ نگهداریِ ۶ماهه دارد. ساختار = بلوکِ پایه (پردازش) + ۳ بلوکِ اختیاریِ مستقل (پیامک/اپ/ثانویه) + صغار (۱۸ سالِ شمسی). ۵ تنشِ وکیل‌خواه علامت خورد.
**گِیت:** بازبینیِ وکیلِ رسمی روی پیش‌نویس (L5).
