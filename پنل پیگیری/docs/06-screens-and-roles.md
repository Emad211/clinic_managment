## ۲. سربرگ مشترک

```
[پنل پیگیری]   شیفت عصر · ۱۴۰۵/۰۷/۱۴ [تغییر]   ● همگام (۳ ثانیه پیش)   دکتر … ▾ [خروج]
```

- **شیفت جاری:** از حسابداری خوانده می‌شود (03 §۱۰). «تغییر» فهرست سه شیفت و تاریخ را باز می‌کند.
- **نشانگر همگام‌سازی:** سبز، زرد یا قرمز (02 §۹). در حالت قرمز یک بنر توضیح می‌دهد چه اتفاقی افتاده و چه باید کرد، مثلاً «فایل حسابداری در مسیر تنظیم‌شده پیدا نشد؛ config.ini را بررسی کنید».

## ۳. ورود

- **فیلدها:** نام کاربری و رمز. نقش انتخاب نمی‌شود.
- **ترتیب تشخیص:**
  1. اگر نام کاربری در حساب‌های پزشک باشد، ورود پزشک انجام می‌شود و `medical_staff` از حسابداری تأیید می‌شود.
  2. در غیر این صورت، کاربر حسابداری بررسی می‌شود: نقش پذیرش یا مدیر.
- **پیام‌های خطا:**
  - «نام کاربری یا رمز نادرست است»
  - «حساب شما در حسابداری غیرفعال یا قفل است»
  - «حساب پزشک شما در کادر درمان حسابداری فعال نیست؛ با مدیر تماس بگیرید»

## ۴. پزشک

### ۴-۱. صف

```
┌───────────────────────────────────────────────────────────────┐
│ صف من — شیفت عصر                         ۱۲ بیمار · ۴ در انتظار │
├───────────────────────────────────────────────────────────────┤
│ ● در انتظار   مریم احمدی      [تست قند]          ۱۷:۲۰        │
│ ● در انتظار   ⚠ خ حسینی       هویت ناقص          ۱۷:۲۴        │
│ ✓ ثبت شد     علی رضایی       تمدید ۲م · فشار     ۱۶:۵۵        │
│ – بدون پیگیری  …                                               │
└───────────────────────────────────────────────────────────────┘
```

- هر ۵ ثانیه تازه می‌شود. ترتیب: «در انتظار» بالا، و بعد بر اساس زمان ویزیت.
- **برچسب‌های کنار نام:** خدمات همان فاکتور (مثل تست قند)، هویت ناقص، و مسیرهای باز قبلی.

### ۴-۲. پنل بیمار

هدف ۳۰ ثانیه است و مسیرهای پیش‌فرض به تایپ نیاز ندارند.

```
┌ مریم احمدی · ۰۹۱۲…۴۵۶۷ · کد ملی …۸۹۰۱ ───────────────────────┐
│ مسیرهای باز: تمدید — موعد ۱۴۰۵/۰۸/۱۲ [لغو]                     │
│                                                                 │
│ بیماری مزمن:   [✓ دیابت]  [ فشار خون ]                           │
│                                                                 │
│ پیگیری:                                                         │
│  تمدید نسخه      ( ۱ ماه ) ( ۲ ماه ) ( ۳ ماه )                    │
│  آزمایش سه‌ماهه  [ ]                                             │
│  سری کنترل قند   [ ]  ۳ نوبت · هر ۱ روز  [✎]                      │
│  سری کنترل فشار  [ ]  ۳ نوبت · هر ۱ روز  [✎]                      │
│  آزمایش نوشته شد [ ]                                             │
│  جراحی سرپایی    [ ]  بخیه: (۵)(۷)(۱۰)(۱۴)  پانسمان: (۱)(۲)(۳)(ندارد) │
│  جرم گوش         ( قطره تجویز شد ) ( تجویز نشد )                  │
│                                                                 │
│ عدد (اختیاری):  فشار [   /   ]   قند [   ] (ناشتا)(غیرناشتا)       │
│ ⓘ تست قند روی همین فاکتور ثبت شده؛ عدد را وارد کنید.            │
│ یادداشت (اختیاری): [                               ]            │
│                                                                 │
│              [ ثبت ]                 [ بدون پیگیری ]              │
└─────────────────────────────────────────────────────────────────┘
```

- **ورود عدد:** با صفحه‌کلید عددیِ روی صفحه؛ بدون نیاز به صفحه‌کلید فیزیکی.
- **«آزمایش سه‌ماهه»** فقط وقتی برچسب دیابت روشن است دیده می‌شود.
- **«جراحی سرپایی»** بدون انتخاب روز بخیه قابل ثبت نیست. پیام: «روز کشیدن بخیه را انتخاب کنید».
- **بیمار با هویت ناقص:** ثبت ممکن است. پیام پس از ثبت: «پیگیری‌ها پس از تکمیل هویت توسط پذیرش فعال می‌شوند».
- **پیام پس از ثبت:** «ثبت شد — ۲ پیگیری ساخته شد»، و پنل بسته می‌شود.

## ۵. پذیرش

یک صفحه با شش زبانه. عدد کنار هر زبانه تعداد موارد باز است.

| زبانه | محتوا | اقدام |
|---|---|---|
| **هویت ناقص** (قرمز) | فاکتورهای بازی که ویزیت، تست قند یا کنترل فشار دارند و هویتشان ناقص است، به‌علاوهٔ مسیرهای `awaiting_identity`. بالای فهرست: «تا بیمار در درمانگاه است تکمیل کنید» | [تکمیل هویت] · [تبعهٔ خارجی است] |
| **کاغذ پرستار** | مراجعه‌های تست قند و کنترل فشار بدون ویزیتِ امروز و دیروز | [ورود اطلاعات] · [کاغذ موجود نیست] |
| **تماس‌های امروز** | نام، موبایل (با دکمهٔ کپی)، دلیل تماس، پزشک مبدأ، تعداد تلاش | دکمه‌های نتیجه (§۵-۳) |
| **عقب‌افتاده‌ها** | تماس‌هایی که موعدشان گذشته، به‌همراه تعداد روز تأخیر | همان دکمه‌ها |
| **انتظار امروز** | نوبت‌های امروز و جلسه‌های سری و پانسمان امروز | [اتصال به فاکتور امروز] |
| **تأیید تطبیق** | پیشنهادهای خودکار (موبایل یکسان) | [همین بیمار است] · [نه] |

### ۵-۱. فرم تکمیل هویت
- **پیش‌پر** از پروندهٔ حسابداری.
- **فیلدها:** نام، نام خانوادگی، کد ملی، موبایل.
- **اعتبارسنجی زنده** طبق 05 §۹. پیام‌ها:
  - «کد ملی نامعتبر است (رقم کنترل)»
  - «موبایل باید ۱۱ رقم و با ۰۹ شروع شود»
  - «نام کوچک کامل وارد شود»
- **اگر کد ملی از قبل وجود داشته باشد:** «این کد ملی متعلق به … است. اتصال؟». اختلاف نام یا موبایل نمایش داده می‌شود و پذیرش انتخاب می‌کند کدام نگه داشته شود.
- **یادآوری ثابت پایین فرم:** «این اطلاعات فقط در پنل ذخیره می‌شود. در مراجعهٔ بعدی، بیمار را در حسابداری با همین کد ملی ثبت کنید.»

### ۵-۲. فرم کاغذ پرستار
- **هویت:** مانند §۵-۱. اگر کامل باشد، فقط نمایش داده می‌شود.
- **فشار:** دو عدد. **قند:** یک عدد، همراه با ناشتا یا غیرناشتا.
- **دارو مصرف می‌کند:** بله / خیر. اگر «بله»، **زمان تقریبی تمدید:** انتخاب تاریخ جلالی، یا دکمه‌های «۱۰ روز دیگر»، «۲۰ روز دیگر»، «۱ ماه دیگر».
- **دستگاه شخصی دارد:** بله / خیر (D23).
- **پس از ثبت:** نتیجهٔ کات‌آف به‌صورت متن نمایش داده می‌شود، مثلاً «دعوت به ویزیت ساخته شد» یا «بدون اقدام». پذیرش انتخابی نمی‌کند (D19).

### ۵-۳. ثبت نتیجهٔ تماس

| دکمه | رفتار |
|---|---|
| **نوبت گرفت** | تقویم جلالی باز می‌شود، همراه با پیشنهاد روز و شیفت پزشک (05 §۱۰) |
| **جواب نداد** | تلاش بعدی فردا. در تلاش سوم، پیش از ثبت هشدار «مسیر بسته می‌شود» نمایش داده می‌شود |
| **نمی‌آید** | تأیید یک‌مرحله‌ای، و مسیر بسته می‌شود. در جرم گوش «تجویز نشد»: تماس دوباره ۳ روز بعد |
| **هنوز آزمایش نداده** | فقط در مسیر آزمایش. تماس دوباره ۳ روز بعد |
| **جواب آماده است** | فقط در مسیر آزمایش. همان «نوبت گرفت» با تاریخ |

- **متن تماس هر دلیل** در کادر بالای دکمه‌ها نمایش داده می‌شود، مثلاً «یادآوری تمدید نسخه — موعد ۱۴۰۵/۰۸/۱۲».
- **یادداشت** اختیاری است.

| صفحه | محتوا |

| **کات‌آف‌ها** | نسخهٔ تأییدشدهٔ فعلی (فقط خواندنی) و پیش‌نویس با فرم قاعده‌ها. برای پزشک مدیر: [تأیید]. برای بقیه: «در انتظار تأیید پزشک مدیر» |
| **پزشکان** | ساخت حساب (نام کاربری، رمز، انتخاب از کادر درمانِ فعال در حسابداری)، پرچم «پزشک مدیر»، غیرفعال‌سازی |
| **پزشکان پیگیری** | انتخاب چند پزشک برای پیشنهاد نوبت (D20) |
| **نگاشت کارهای عملی** | نام‌های متنیِ بدون دسته یا مبهم، همراه با تعداد ردیف. برای هر کدام یکی انتخاب می‌شود: پانسمان، کشیدن بخیه، شستشوی گوش، یا نامرتبط |
| **گزارش** | مسیرها به تفکیک الگو و وضعیت؛ نرخ موفقیت به تفکیک الگو و پزشک مبدأ، در کنار مبنای ۸٪؛ سهم بازگشت نزد همان پزشک؛ تلاش‌های تماس به تفکیک کاربر؛ رعایت هویت به تفکیک کاربر پذیرش و شیفت |
| **لاگ ممیزی** | جستجو بر اساس کاربر، تاریخ و نوع کار |
| **سلامت** | خروجی `/health` (02 §۹) و [توقف برنامه] |
| **بررسی پیگیری‌ها** (`/review`) | مسیرهای «نیازمند بررسی» (G12) با [ادامهٔ پیگیری] · [لغو پیگیری]. پزشک همین کارت را برای مسیرهای خودش بالای صف می‌بیند؛ پزشک مدیر و مدیر همه را |

## ۷. قراردادهای رابط کاربری

- **ظاهر:** راست‌به‌چپ، فونت Vazirmatn از فایل محلی، ارقام فارسی، تاریخ جلالی. هیچ منبعی از اینترنت بارگذاری نمی‌شود.
- **تازه‌سازی:** فهرست‌ها هر ۵ تا ۱۰ ثانیه با `fetch` تازه می‌شوند و صفحه دوباره بارگذاری نمی‌شود. فرمِ در حال ویرایش با تازه‌سازی پاک نمی‌شود.
- **متن دکمه‌ها** دقیقاً همان کاری را می‌گوید که انجام می‌دهد، و پیام نتیجه با همان فعل می‌آید («ثبت شد»).
- **پیام خطا** می‌گوید چه چیزی غلط است و چطور درست شود.
- **کد ملی** در فهرست‌ها با چهار رقم آخر نمایش داده می‌شود و در فرم‌ها کامل.
- **دسترسی‌پذیری:** دکمه‌ها برای لمس دست‌کم ۴۴ پیکسل‌اند، فوکوس صفحه‌کلید دیده می‌شود، و رنگ تنها نشانهٔ وضعیت نیست؛ نماد و متن هم کنارش هست.
