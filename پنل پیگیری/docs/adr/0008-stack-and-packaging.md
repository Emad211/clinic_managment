# ADR-0008 — استک و بسته‌بندی

- **وضعیت:** پذیرفته‌شده — ۱۴۰۵/۰۷/۱۴
- **مرتبط:** D02، D07، [02 §۷](../02-architecture.md)

## زمینه

- پنل باید دقیقاً مانند حسابداری اجرا شود: exe، دوبار کلیک، باز شدن مرورگر (D07).
- محیط دو کامپیوتر ویندوزی در شبکهٔ داخلی است و ممکن است اینترنت نداشته باشد.
- build موجود حسابداری در `webapp/build` با Python 3.13 ساخته شده است.

## تصمیم

**استک:**
- Python 3.13
- Flask و Jinja2: صفحه‌های سمت سرور و راست‌به‌چپ
- جاوااسکریپت ساده با `fetch` برای تازه‌سازی فهرست‌ها
- SQLite در حالت WAL برای دیتابیس پنل
- `bcrypt` و `jdatetime`

**دارایی‌های محلی:** Vazirmatn و `jalaali.js` داخل exe قرار می‌گیرند و هیچ CDNی استفاده نمی‌شود.

**بسته‌بندی:**
- PyInstaller، تک‌فایلی، `console=False`، با نام `PeygiriPanel.exe`.
- قالب‌ها، فایل‌های static، `schema.sql` و `journeys/*.json` در `datas` بسته‌بندی می‌شوند.
- مسیرها در دو حالت کار می‌کنند: حالت منبع، و حالت exe از طریق `sys._MEIPASS`.

**اجرا:**
- سرور توسعهٔ werkzeug، چندنخی، روی `0.0.0.0:8091`؛ مانند حسابداری.
- نگهبان تک‌نمونه.
- مرورگر پس از ۱٫۵ ثانیه باز می‌شود.

**نام‌ها:** نام پوشه فارسی است، ولی همهٔ نام‌های داخلی (پکیج، exe، فایل‌ها) ASCII هستند.

## پیامدها

- مدل اجرا و نگهداری عیناً مثل حسابداری است و برای کاربران و توسعه‌دهنده آشناست.
- بدون اینترنت کار می‌کند.
- سرور توسعه برای اینترنت ساخته نشده، ولی برای دو کاربرِ شبکهٔ داخلی کافی است. فهرست اختیاری IPهای مجاز و نبود هیچ دسترسی بیرونی، این ریسک را کنترل می‌کنند.

## گزینه‌های ردشده

| گزینه | دلیل رد |
|---|---|
| Django یا Next.js | برای ابزار محلیِ دوکامپیوتری سنگین‌اند. استک ابری پروژه برای محصول دیگری است |
| Electron | حجم زیاد؛ استک تازه |
| سرور WSGI جدا (مثل waitress) | برای دو کاربر لازم نیست. اگر لازم شد، بدون تغییر لایه‌ها اضافه می‌شود |
