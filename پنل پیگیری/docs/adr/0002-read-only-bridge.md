# ADR-0002 — پل فقط‌خواندنی SQLite

- **وضعیت:** پذیرفته‌شده — ۱۴۰۵/۰۷/۱۴
- **مرتبط:** D03، D04، [03-accounting-bridge.md](../03-accounting-bridge.md)

## زمینه

- دیتابیس حسابداری ۱۰۸ مگابایت است و در حالت `journal_mode=DELETE` کار می‌کند.
- در این حالت، قفل SHARED خواننده جلوی commit نویسنده را می‌گیرد. حسابداری تا ۵ ثانیه صبر می‌کند و بعد خطای «database is locked» می‌دهد، که روی صفحهٔ پذیرش ظاهر می‌شود.
- پس خطر واقعی خواندن، **نگه داشتن طولانی قفل** است. خودِ «فقط خواندن» به‌تنهایی کافی نیست.

## تصمیم

**اتصال:**
- URI `file:…?mode=ro`، همراه با `PRAGMA query_only=ON`.
- `timeout` اتصال ۲۵۰ میلی‌ثانیه. اگر حسابداری مشغول باشد، چرخه رد می‌شود.

**چرخه:**
- هر چرخه یک تراکنش خواندنی صریح دارد.
- سقف سخت ۲۰۰ میلی‌ثانیه با `set_progress_handler`.
- نتیجه‌ها فوراً با `fetchall` خوانده می‌شوند و اتصال در پایان هر چرخه بسته می‌شود.

**کوئری‌ها:**
- فقط کوئری‌های فهرست‌شده در 03 §۵.
- همه روی کلید اصلی یا ایندکس موجود، با ستون‌های صریح.

**ممنوع:**
- هر نوع نوشتن، و PRAGMAهای نویسنده
- تغییر حالت ژورنال به WAL
- `immutable` و `nolock`
- `ATTACH` دیتابیس حسابداری
- کپی فایل
- import از `webapp`

## پیامدها

- **اندازه‌گیری‌شده روی کپی تولید (M0):** هر چرخه از باز کردن تا بستن اتصال میانه ۱٫۷۵ و صدک ۹۹ برابر ۲٫۵۷ میلی‌ثانیه.
- **صبر هنگام مشغولی در پایتون است، نه در SQLite** (`timeout=0`)، چون busy handler در ویندوز به تیک تایمر گرد می‌شود و سقف ۲۵۰ میلی‌ثانیه را نگه نمی‌داشت.
- **اثبات‌شده:** تلاش برای نوشتن روی اتصال پل رد می‌شود.
- **هزینه:** در لحظه‌های پرنوشتن، یک چرخه ممکن است رد شود. دادهٔ پنل حداکثر حدود ۱۰ ثانیه عقب است.
- **قید دائمی:** هر کوئری تازه باید پیش از ادغام آزمون طرح اجرا را پاس کند (03 §۱۱).

## گزینه‌های ردشده

| گزینه | دلیل رد |
|---|---|
| تغییر دیتابیس حسابداری به WAL | نوشتن روی سربرگ فایل و تغییر رفتار حسابداری؛ خلاف D03 |
| کپی کامل فایل هر چند ثانیه | خطر کپیِ نیمه‌نوشته؛ ۱۰۸ مگابایت ورودی/خروجی در هر چرخه |
| snapshot با API بکاپ SQLite در هر چرخه | خواندن کل دیتابیس؛ یا قفل طولانی، یا قدم‌های زیاد |
| trigger یا جدول outbox در حسابداری | نوشتن در دیتابیس حسابداری |
| خواندن از صفحه‌های وب حسابداری | حسابداری API ندارد؛ بار روی برنامهٔ پذیرش؛ شکننده |
