# پنل پیگیری

برنامه‌ای مستقل که کنار نرم‌افزار حسابداری درمانگاه (`../webapp`) اجرا می‌شود. بیمارِ نیازمند پیگیری را از لحظهٔ ویزیت یا مراجعهٔ پرستاری در یک **مسیر** قرار می‌دهد، تماس‌ها را برای پذیرش زمان‌بندی می‌کند و **بازگشت** بیمار را از روی پرداخت‌های ثبت‌شده در حسابداری تشخیص می‌دهد.

ارتباط با حسابداری **فقط خواندنی** است. این برنامه هیچ‌چیز در دیتابیس حسابداری نمی‌نویسد و هیچ تغییری در نرم‌افزار حسابداری لازم ندارد.

**وضعیت:** M0 کامیت شده (`92307517`) و M1 پیاده‌سازی و محلی آزموده شده است (۱۴۰۵/۰۷/۱۴). نسخهٔ برنامه ۰٫۲٫۰ و اسکیما ۲ است. مرحلهٔ بعد M2 (هویت) است. جزئیات و محدودیت‌های آزمون در [گزارش M1](docs/m1-verification.md).

## پنج اصل غیرقابل‌مذاکره

1. **حسابداری فقط خوانده می‌شود.** تنها ماژولی که فایل حسابداری را باز می‌کند `src/adapters/accounting/` است. اتصال فقط‌خواندنی است، هدف صدک ۹۹ چرخهٔ خواندن کمتر از ۵ میلی‌ثانیه است؛ اندازه‌گیری M0 روی کپی تولید ۲٫۵۷ میلی‌ثانیه بود، و اگر حسابداری مشغول باشد پنل کنار می‌کشد ([ADR-0002](docs/adr/0002-read-only-bridge.md)).
2. **صفحه‌ها هیچ‌وقت مستقیم از حسابداری نمی‌خوانند.** فقط پایشگر می‌خواند و نتیجه را در «آینه» داخل دیتابیس پنل می‌ریزد. بار روی حسابداری ثابت و قابل پیش‌بینی است ([ADR-0003](docs/adr/0003-incremental-polling.md)).
3. **هیچ کدی از `webapp` یا `specialist_clinic` import نمی‌شود.** تابع `get_db()` حسابداری هنگام اتصال migration اجرا می‌کند، یعنی می‌نویسد ([ADR-0001](docs/adr/0001-independent-app.md)).
4. **بدون هویت کامل، پیگیری شروع نمی‌شود.** نام کامل، کد ملی معتبر و موبایل لازم است. اتباع خارج از پیگیری‌اند ([ADR-0004](docs/adr/0004-identity.md)).
5. **پیش‌فرض‌ها و قواعد در داده‌اند، نه در کد.** الگوهای مسیر، پیش‌فرض‌ها و کات‌آف‌ها بدون تغییر کد عوض می‌شوند. کات‌آف‌ها فقط با تأیید پزشک مدیر فعال می‌شوند ([ADR-0005](docs/adr/0005-journey-engine.md)، [ADR-0009](docs/adr/0009-clinical-cutoffs.md)).

## نام‌ها و مقادیر فنی

| مورد | مقدار |
|---|---|
| نام برنامه | پنل پیگیری |
| فایل اجرایی | `PeygiriPanel.exe` (تک‌فایلی، بدون پنجرهٔ کنسول) |
| پورت | `8091` (حسابداری روی `8080`) |
| دیتابیس پنل | `peygiri_panel.db` کنار exe |
| تنظیمات | `config.ini` کنار exe |
| پکیج پایتون | `src/`؛ همهٔ نام‌های داخلی ASCII |

نام پوشه فارسی و با فاصله است. برای اینکه ابزارهای ساخت و خط فرمان دچار مشکل نشوند، همهٔ نام‌های داخلی (پکیج، exe، فایل‌ها) ASCII هستند. در خط فرمان مسیر پوشه را داخل کوتیشن بنویسید.

## واژه‌نامه

| واژه | معنی |
|---|---|
| **مسیر** (journey) | یک نمونهٔ پیگیری برای یک شخص، مثل «تمدید نسخه» یا «جرم گوش» |
| **الگوی مسیر** (template) | تعریف داده‌محور یک نوع مسیر: قدم‌ها، فاصله‌ها و پیش‌فرض‌ها |
| **قدم** (step) | جزء مسیر: **تماس** (call) در یک روز مشخص، یا **انتظار خدمت** (expect) در یک بازهٔ زمانی |
| **بازگشت** (return) | پرداخت خدمتِ مورد انتظار یک قدم، روی فاکتوری از همان شخص |
| **مدرک بازگشت** (evidence) | ارجاع به آیتم پرداخت‌شدهٔ حسابداری که یک قدم را برآورده کرده است |
| **شخص** (person) | هویت یکتا در پنل، بر پایهٔ کد ملی |
| **پروندهٔ حسابداری** | یک ردیف `patients` در حسابداری. یک شخص ممکن است چند پرونده داشته باشد |
| **مراجعهٔ پرستاری** (walk-in) | فاکتوری با «تست قند» یا «کنترل فشار» و بدون ویزیت |
| **کات‌آف** (cut-off) | آستانهٔ عدد فشار یا قند که اقدام خودکار را تعیین می‌کند؛ با تأیید پزشک مدیر |
| **سری کنترل** | چند نوبت اندازه‌گیری در درمانگاه با فاصلهٔ مشخص (همان SMBG/SMBP در درمانگاه) |
| **پزشک مبدأ / پزشک انجام‌دهنده** | پزشکی که مسیر را ساخته / پزشکی که خدمت بازگشت را انجام داده |
| **پزشک مدیر** | حساب پزشکی که اجازهٔ تأیید کات‌آف‌ها را دارد |
| **آینه** (mirror) | کپی محدودی از فاکتورها و آیتم‌های اخیر حسابداری داخل دیتابیس پنل |
| **پایشگر** (poller) | thread پس‌زمینه‌ای که هر چند ثانیه حسابداری را می‌خواند |
| **شیفت جاری** | شیفتی که پذیرش در حسابداری فعال کرده، با امکان تغییر دستی |
