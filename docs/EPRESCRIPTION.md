# نسخهٔ الکترونیک — امکان‌سنجی و تصمیمِ اتصال (E-Prescription)

> **نسخه ۱.۰ — خرداد ۱۴۰۵ — Spikeِ Epic 1 ([`FEATURES.md`](FEATURES.md)).**
> منبع: تحقیقِ خرداد۱۴۰۵. ⚠️ بسیاری از صفحاتِ دولتی (`tamin.ir`, `ep.tamin.ir`, `ihio.gov.ir`) از بیرونِ
> ایران geo-block/timeout دارند؛ بخشی از جزئیاتِ فنی فقط **از داخلِ ایران** قابلِ‌تأیید است (پایین علامت خورده).

## خلاصهٔ تصمیم (TL;DR) — مسیرِ سه‌گانه
**نتیجهٔ کلیدی:** اتصالِ مستقیمِ API به بیمه‌ها یک **ماراتنِ گواهیِ ۶–۱۲+ ماهه** است (صلاحیتِ هر بیمه + گواهیِ امنیتیِ افتا که به‌تنهایی ~۱ سال). پس **نباید** دروازهٔ MVP باشد. تصمیم:
- **مسیر A — همین حالا (MVP): پُلِ WebView.** پورتالِ رسمیِ بیمه (`ep.tamin.ir` / `eservices.ihio.gov.ir`) را داخلِ اپ embed می‌کنیم؛ پزشک همان‌جا نسخه می‌پیچد، ولی در جریانِ کارِ محصولِ ما. محصول **بدونِ گواهی، همین حالا فروش‌پذیر/پایلوت‌پذیر** است.
- **مسیر B — موازی، از روزِ اول: فرایندِ گواهی.** ثبت‌نامِ شرکت + شروعِ گواهیِ افتا و صلاحیتِ تأمین/سلامت (long-lead؛ از روزِ اول کلید بخورد). وقتی گرفتیم، WebView → API بومی سویچ می‌شود (UX یکپارچه).
- **مسیر C — ارزیابی: شراکت/کانکتور.** بررسیِ شراکت با یک شرکتِ از پیش‌گواهی‌دار یا میدل‌ویر، برای میان‌بُر.

**اثرِ استراتژیک:** بقیهٔ فاز۱ (تمایزِ واقعی: Snapshot, Recall, Guardrails, Practice Intelligence) **بلاک نیست** و می‌تواند فوری پیش برود.

## ۱. مدل‌های اتصال (سطحِ اطمینان: بالا)
| مدل | شرح | برای ما |
|---|---|---|
| **پورتالِ دستی** | پزشک در مرورگر واردِ `ep.tamin.ir` / `eservices.ihio.gov.ir` می‌شود؛ بدونِ یکپارچگیِ نرم‌افزار. | پایه؛ تجربهٔ ضعیف. |
| **WebService/API مستقیم** | فقط برای نرم‌افزارهای **دارای گواهیِ صلاحیت**؛ نسخه از داخلِ نرم‌افزار ارسال می‌شود. ~۱۸ نرم‌افزار از بیمهٔ سلامت گواهی گرفته‌اند. | هدفِ نهایی (مسیر B). |
| **پُلِ WebmView (embedded)** | پورتالِ رسمی داخلِ اپ embed می‌شود؛ چند فروشنده این را به‌عنوانِ گزینهٔ موقت تا اخذِ گواهی ارائه می‌دهند. | **MVP (مسیر A).** |

**سه بیمهٔ مجزا:** تأمین اجتماعی · بیمهٔ سلامت (IHIO) · نیروهای مسلح — هرکدام **API و گواهیِ جداگانه**. برای سرپایی، تأمین + سلامت اولویت دارند.

## ۲. مسیرِ گواهی (long-lead — سطحِ اطمینان: متوسط)
1. شرکتِ ثبت‌شده با صلاحیتِ فنی (احتمالاً عضویتِ نظامِ صنفیِ رایانه‌ای).
2. درخواست به واحدِ فناوریِ هر بیمه (تأمین: احتمالاً `apiissue.tamin.ir`).
3. **گواهیِ ارزیابیِ امنیتیِ افتا** (مرکزِ افتای ریاست‌جمهوری) — کیمیا آفیس: «بیش از یک سالِ فشرده». ⚠️ الزامی‌بودنِ قطعیِ افتا برای همهٔ موارد تأییدِ نهایی نشد، ولی نشانه‌های قوی دارد.
4. آزمونِ عملکردی در محیطِ تست → صدورِ **گواهیِ صلاحیتِ عملکرد** → تحویلِ مستنداتِ API و credential.
- **مستنداتِ API فقط پس از گواهی** در اختیار قرار می‌گیرد (هیچ مستندِ عمومی بیرون نیست).
- **تخمینِ کل: ۶ تا ۱۲+ ماه.**

## ۳. احرازِ پزشک (سطحِ اطمینان: متوسط-بالا)
کدِ ملی + OTP موبایل + استعلامِ خودکارِ نظامِ پزشکی + احتمالاً **امضای دیجیتالِ دریافتی از نظامِ پزشکی**. نیازی به **قراردادِ** بیمه‌ای نیست (پزشکِ طرف/غیرطرفِ قرارداد هر دو می‌توانند). جزئیاتِ فنیِ امضای دیجیتال از بیرون تأیید نشد.

## ۴. کانکتور/شراکت (سطحِ اطمینان: متوسط)
- **«شرکتِ دانش‌بنیان راهکار» (labsolutions.ir)** «افزونهٔ نسخهٔ الکترونیک» دارد، ولی **برای محصولاتِ خودش**، نه به‌عنوانِ کانکتورِ عمومیِ قابلِ‌لایسنس. کانکتورِ تجاریِ آماده و شفاف یافت نشد.
- **نتیجه:** میان‌بُرِ «یک کانکتور بخر و گواهی نگیر» محتمل نیست؛ احتمالاً باید **خودمان گواهی بگیریم** (مسیر B) یا با یک فروشندهٔ گواهی‌دار **شراکت** کنیم (مسیر C — نیازمندِ مذاکره).

## ۵. اثر روی Epic 1 و فاز۱
- Epic 1 از «بلاکرِ ۱‌ساله» به **«WebView حالا + گواهی موازی»** تبدیل شد.
- **اقدامِ long-lead (روزِ اول):** ثبت‌نامِ شرکت + شروعِ فرایندِ افتا/صلاحیت — چون زمان‌بَر است و موازی پیش می‌رود.
- **MVP:** WebView bridge؛ تمرکزِ مهندسی روی لایهٔ تمایز (مدیریتِ مزمن).
